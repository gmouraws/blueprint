# ADR 020: Opt-in Windows process audio in the private desktop test build

Status: implemented. After local verification, the owner explicitly authorized publishing 0.1.4 to Production for manual acceptance, superseding the initial private-only restriction.

Electron 45 exposes system loopback or an Electron-owned WebFrameMain, not arbitrary external application audio. Use an original, small x64 C++ helper against Microsoft's documented process-loopback API. No third-party native library, driver, service, recording, or injection is added. Electron remains pinned; sandbox, context isolation, exact origins and existing permissions remain enabled.

The local picker enumerates all Electron sources, refreshes explicitly, preserves surviving selection, and never filters on thumbnail availability. Search only affects presentation. Main re-enumerates the selected ID. The helper resolves its HWND with GetWindowThreadProcessId, holds a process handle, verifies ownership/liveness and rejects Blueprint's process tree and ancestors. Remote content cannot submit a PID or HWND to the helper. Only an explicit, current picker grant can create a one-use audio session; pulls and release require the trusted top frame, active call and opaque grant ID.

Windows build 20348+ is required. Actual activation can still fail for protected/inaccessible targets. Capture includes the selected owning process and its descendants; it is not a per-tab/per-window audio boundary. Independently launched sibling audio services are not guessed or included. Failure never selects system audio. The default is Sem áudio; application audio remains explicitly experimental during user acceptance.

The helper requests stereo 48 kHz PCM16 with Windows conversion, emits float32 packets over stdout, and uses WASAPI QPC timestamps. Main drains into a maximum 100 ms queue, dropping oldest packets rather than accumulating latency. A single outstanding pull feeds AudioData/MediaStreamTrackGenerator in the preload-installed getDisplayMedia adapter; it never connects to local speakers. LiveKit receives an ordinary screen audio track through the existing capture/publication path. No hosted web change is needed. This deliberately depends on pinned Chromium/Electron APIs and must be retested before upgrading them.

Stopping either capture track releases both display tracks and the helper. Target/window exit ends sharing; navigation, call unavailability, stale call heartbeat, logout, cancellation and explicit application exit release the helper. A lost reader is terminated after five seconds. Pipe buffers and one outstanding AudioData are bounded; no captured samples are written to disk. Session/audio state is never persisted. Physical AV synchronization and long-running games remain acceptance tests, not claims from packet timestamps.

Build uses the locally installed MSVC x64 tools and Windows SDK, static runtime, ASLR/NX and no elevation. The original helper needs no additional third-party license; existing Electron/Chromium notices remain in the package. SDK/runtime redistribution follows the installed Microsoft toolchain license. Only the helper executable is an extra resource; fixtures, native sources, credentials and development tools are excluded from the installer. The reviewed release gate authorizes only 0.1.4 after main Quality passes; published assets are immutable. Update the website manifest only after downloading and verifying the actual published installer/checksum.
