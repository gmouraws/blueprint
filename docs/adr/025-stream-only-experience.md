# ADR 025 — Stream-only product and demand-driven media

Status: owner approved implementation and Production release after checks. Supersedes member rooms/chat as the normal product navigation, without deleting historical data or removing protected legacy APIs.

The owner manually validated Windows 0.1.6 and the current streaming quality before this work. The home page is now a media-free streaming entry. `/admin` retains account login, profile management, and owner-only invitation administration. The account backend, persisted preferences, legacy chat records/attachments, revocation mechanisms and retention jobs remain. Retired member-room browser scenarios are retained under tests/retired-e2e for historical reference, outside the active stream-only browser suite; backend ownership/security tests remain active.

A validated guest session can poll `discover` without a LiveKit SDK connection. Discovery uses the existing fenced ledger and provider participant list; it returns only authorized active screen publishers and public guest labels/track identities, never credentials. It allocates no room, token or participant identity. Ten-second polling consumes Redis/API requests, not WebRTC participant minutes. Signed provider events remain the independent announcement mechanism.

Capture selection precedes admission, so cancelling the browser/native picker consumes no participant minutes. The guest native capture heartbeat now represents active invitation authorization, not already-connected media. Explicit user gesture, screen-source selection, session expiry and restricted IPC still apply. Publishing or explicitly choosing an active stream acquires a single connection. Only the selected remote screen and its audio are subscribed. Stopping publication releases admission unless the user is also watching. A vanished selected publisher gets a 20-second discovery grace before the viewer disconnects; discovery errors are not treated as proof of media ending. Active minimized/tray sessions stay connected. Application exit and guest revocation still stop media.

The stream UI offers 30/60 fps, defaulting to 30 for new shares. Both use the existing 1080p targets, codecs and adaptive behavior; 30 retains the existing balanced 5 Mbps ceiling and 60 retains the existing detail 8 Mbps ceiling. There is no new 720p or 2.5 Mbps preset and no promise of proportional bandwidth savings. Fewer frames do not reduce participant minutes.

Device-local measurements retain at most 28 daily numeric aggregates: connected duration and sampled sent/received video/audio bytes, plus the last measured video dimensions/fps. No content, credentials, invitations or user/participant identities are persisted. Metrics are approximate and may undercount short sessions, suspension and failed samples; they exclude protocol overhead and cannot replace Cloud billing. Local users can clear them. Detailed viewer statistics show measured outbound video bitrate separately from audio.

Windows 0.1.7 removes retired tray mute controls while preserving protocol handling, guest isolation and shutdown ordering. No service purchase, schema migration, signing purchase or automatic update is introduced. Keep the published 0.1.6 download until the real 0.1.7 Production asset is downloaded and hash-verified, then update the manifest separately.

Recovery: restore the recorded pre-change web commit/deployment and the verified 0.1.6 manifest if needed. Installed clients require manual update/downgrade. Preserve all invitation/account/history/journal data. A code rollback alone cannot disconnect media; revoke affected invitations and confirm cleanup when required.
